# SEO-кейс vega-msp.ru — рабочий процесс репозитория

## Когда применять

Любая задача в этом репозитории: понять структуру, обновить описание кейса, проверить README перед публикацией, исправить ошибки оформления, подготовить коммит и push.

## Карта репозитория

| Путь | Назначение |
|---|---|
| `README.md` | публичное описание SEO-кейса: проблема, пользователь, функции, результат, технологии |
| `.claude/skills/vega-msp-seo/SKILL.md` | этот скилл |
| `.claude/skills/vega-msp-seo/scripts/check_readme.py` | проверка структуры README, ссылок и запрещённых данных |

## Что это за репозиторий

- Это **публичный кейс**, а не приложение: здесь только описание проекта и проектный скилл.
- В репозитории **нет** запускаемого сервиса, сборки, зависимостей и базы данных.
- Исходные скрипты, доступы, конфигурации и внутренние данные остаются вне репозитория.
- Клиника и домен указаны публично по решению владельца проекта.

## Запуск и предпросмотр

Сервиса в репозитории нет, поэтому `npm install`, `node server.js` и подобные команды здесь не применяются.

Для проверки текста:

1. Откройте `README.md` в редакторе с Markdown Preview (VS Code, Obsidian и т.п.).
2. Или смотрите отрендеренную версию на GitHub: https://github.com/atregubov87-svg/vega-msp-seo
3. Для автоматической проверки:

```bash
python .claude/skills/vega-msp-seo/scripts/check_readme.py
```

Если в будущем появится демо-сайт или docs-сервис, добавьте команды запуска в этот раздел и обновите карту репозитория.

## Внесение изменений

- Меняйте только `README.md` и файлы скилла; не добавляйте сюда код, конфиги и секреты.
- Сохраняйте структуру кейса: название → проблема → пользователь → основная функция → формат результата → минимальный функционал → технологии.
- Если появились новые проверенные цифры, обновляйте таблицу «Результаты в цифрах» и не смешивайте экспертную оценку с позициями в поиске.
- Если нужно обезличить клинику, заменяйте название и домен **везде** одновременно, включая заголовок, проблему, автора и ссылки.
- Не добавляйте ссылки на приватные репозитории и внутренние ресурсы.
- Тон — фактический, без обещаний «топ-1» и неподтверждённых результатов.

## README

`README.md` держится в формате проектного документа:

1. Название
2. Проблема
3. Пользователь
4. Основная функция — Вход / Обработка / Выход
5. Формат результата
6. Минимальный функционал
7. Технологии
8. Результаты в цифрах
9. Безопасность публикации
10. Автор

При изменении функций обновляйте разделы 4, 6 и 8. При изменении стека — раздел 7. При изменении состава репозитория — карту в этом скилле.

## Проверка ошибок

1. Запустите проверку README:

```bash
python .claude/skills/vega-msp-seo/scripts/check_readme.py
```

2. Проверьте diff на пробелы и конфликтные маркеры:

```bash
git diff --check
git status --short
```

3. Просмотрите отрендеренный README на GitHub: заголовки, таблицы, якоря содержания, ссылки.
4. Если доступен markdownlint, можно дополнительно выполнить:

```bash
npx --yes markdownlint-cli2 README.md
```

5. Убедитесь, что в тексте нет паролей, токенов, внутренних IP, имён таблиц МИС, ID счётчиков и служебных адресов.

## Подготовка к публикации

1. `git status --short` — в индекс должны попасть только README и файлы скилла.
2. `git diff` — проверить смысл изменений и отсутствие секретов.
3. `python .claude/skills/vega-msp-seo/scripts/check_readme.py` — проверка должна завершиться `OK`.
4. Добавить файлы:

```bash
git add README.md .claude/skills/vega-msp-seo
```

5. Коммит с понятным сообщением на русском и строкой:

```text
Co-Authored-By: Claude Code <noreply@anthropic.com>
```

6. Push:

```bash
git push origin main
```

7. Проверить, что репозиторий публичный:

```bash
gh repo view atregubov87-svg/vega-msp-seo --json visibility,url
```

Если `gh` не в PATH, используйте полный путь `C:\Program Files\GitHub CLI\gh.exe`.

8. Проверить, что скилл появился в репозитории:

```bash
gh api repos/atregubov87-svg/vega-msp-seo/contents/.claude/skills/vega-msp-seo/SKILL.md --jq .path
```

## Никогда не коммитить

- пароли, токены, API-ключи и секретные заголовки;
- строки подключения к БД и внутренние IP-адреса;
- названия внутренних таблиц и представлений МИС;
- ID счётчиков аналитики и служебные email;
- персональные данные пациентов и сотрудников;
- ссылки на админку и внутренние ресурсы;
- локальные пути вида `D:\ClaudeCode\...`.

## Границы репозитория

Репозиторий существует как публичный кейс и портфолио. Любые рабочие скрипты, конфигурации, выгрузки и доступы хранятся в закрытом рабочем проекте и в этот репозиторий не попадают.
